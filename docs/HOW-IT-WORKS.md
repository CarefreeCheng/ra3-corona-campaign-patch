# 原理说明（给会用一点电脑的人看）

## 一句话

日冕在**遭遇战**里给建筑挂的是"扩展版类型"（例如 `SovietPowerPlantAdvanced_Enhanced`），而**战役**用的是原版类型。我们做的事情就是：在战役里把"原版类型"换成"扩展版类型"，并且是在建筑**出生之前**换，所以技能、建造页、科技全都跟着扩展模式走了。

## 三个问题分别是怎么修的

### 1. 卡关（盟军第一关 / 苏联第八关）

战役脚本靠一串"标记"（flag / timer）来推进目标。日冕改动了单位配置（比如原版第一关会有一队苏联巡逻队，日冕下没有），导致写标记的触发器永远不成立，而目标又必须等这个标记。

补丁不硬改目标，而是**等目标的条件都满足了、只剩这个标记时，把标记补上**，让游戏自己完成目标。所以流程、动画、语音都还是游戏原生的。

### 2. 扩展建筑栏

建造页的按钮表叫 `CommandSet`。日冕给每个阵营准备了两套：原版版和扩展版。补丁在游戏里识别出"建造者"的按钮表，把它指向扩展版那一套，于是建造页多出扩展建筑。

### 3. 建筑技能（预充能线圈等）

建筑能按哪些按钮，是在**建筑被创建的那一刻**定死的；之后再改类型也不会刷新按钮。

所以补丁卡在"类型查表"这一步：游戏要创建"超级反应堆"时，会先拿 `SovietPowerPlantAdvanced` 的哈希去查它的类型定义。补丁把这个查询的入参换成 `SovietPowerPlantAdvanced_Enhanced` 的哈希，游戏拿到的就是扩展版定义，**创建出来的建筑天生就是扩展版**。

> 这就是为什么"地图自带的老建筑"需要**重新载入关卡**：老建筑是在补丁生效之前创建的。

## 为什么用 `xinput1_3.dll` 当载体

Windows 加载 DLL 时优先找"exe 所在目录"里的同名文件。游戏的 exe 在 `Data\ra3_1.12.game`，所以 `Data\` 里的同名 DLL 会先被加载。

选 `xinput1_3.dll` 是因为：

- 它在游戏导入表里（不装它游戏照样能跑，但游戏确实会请求它）
- 它不是系统 `KnownDLLs`（不会被强制替换成系统版）
- 它只负责手柄，键鼠和音频完全不经过它 —— 最坏情况是"手柄失灵"，不会影响正常游玩

## 数据流

```
启动器 -> ra3_1.12.game
              |
              +-- 加载 Data\xinput1_3.dll（我们的代理）
                     |
                     +-- 立刻把真正的系统 xinput 转发过去（游戏感知不到）
                     +-- 20 秒后：LoadLibrary(ra3copilot.dll)
                     |      -> 游戏内出现 HTTP 接口 127.0.0.1:17832
                     +-- LoadLibrary(csprobe.dll)
                     |      -> 扫描 "xxx_Enhanced" 名字，建哈希配对表
                     |      -> 在 0x007E4230 挂 7 字节跳转，改写入参哈希
                     +-- 拉起 ra3fix_helper.exe
                            -> 等接口就绪
                            -> 开 0x1D（扩展建筑栏）、关 0x1E（跳过科技树的副作用）
                            -> 改写建造按钮的产出类型
                            -> 扫描已放置建筑并改写类型
```

## 为什么每一步都要这么绕

- **20 秒延迟**：注入太早（渲染/脚本引擎还没初始化）会把游戏带崩。
- **先注入 copilot 再打补丁**：所有偏移、结构都是运行时拿到的，不依赖硬编码数据。
- **建筑类型改成"扩展版"而不是加按钮**：按钮表是只读数据，加按钮要重建整张表，风险高得多。

更细的偏移和踩坑记录见 [TECHNICAL.md](TECHNICAL.md)。
